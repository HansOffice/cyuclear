# CyuClear 常见问题与排查

## 1. 该选哪个运行包

- **Paper / Purpur 1.13+**：选择 `cyuclear-paper-1.4.5.jar`
- **Folia 1.20+**：选择 `cyuclear-folia-1.4.5.jar`，针对区域线程池与异步实体事件专门优化
- **1.8 至 1.12 旧端**：选择 `cyuclear-legacy-1.4.5.jar`

每台服务端只需在 `plugins/` 目录放入对应的一个 jar，不需要同时放入多个

## 2. 为什么安装后没有任何清理动作

全新安装的 CyuClear 默认将 `config.yml` 中的 `enabled` 设置为 `false`，处于安全停机状态。控制台会输出黄色提示，避免新装插件直接按默认规则删掉服内正在流通的特殊物品。

排查与启用步骤：
1. 拿着常用贵重物品输入 `/cc check`，确认是否被规则正确判定为保护
2. 输入 `/cc preview` 预演一次全服扫描，确认预计清理数量合理
3. 打开 `config.yml`，将 `enabled: false` 改为 `enabled: true`
4. 在控制台或游戏内执行 `/cc reload`，清理定时器随即开始运转

## 3. 区块实体限制中「安全模式」与「严格模式」的区别

在 `rules.yml` 的 `limits.chunk.entities.mode` 中可配置两种限制模式：

- **SAFE（安全模式，默认推荐）**：只统计短时间内的生怪压力与峰值频率，不会在实体生成事件中高频遍历整个区块所有实体。对服务器性能零负担，完全避免跨区域死锁，适合绝大多数生存与空岛服
- **STRICT（严格模式）**：在生物出生和射弹发射入口实时读取区块内的存活实体总数，一旦超过 `max-per-chunk` 立即取消生成。适合高压防刷怪塔的极限压测服

## 4. 虚空垃圾桶放入潜影盒或容器会丢失里面的物品吗

不会。CyuClear 对所有带有内部物品快照的容器（如潜影盒、末影包或拓展背包）均采用完整 NBT 快照捕获，在存入垃圾桶、玩家取出以及批次撤销时，均会核对数据完整性。若快照校验不一致，物品会直接保留在当前世界，绝不产生吞物

## 5. 菜单里的 CraftEngine / ItemsAdder 图标显示成石头

当自定义物品插件重载或异步加载慢于 CyuClear 时，可能出现暂时找不到对应材质的现象。排查步骤：
1. 确认配置中的物品前缀书写正确，例如 `ce:命名空间:物品ID` 或 `ia:命名空间:物品ID`
2. 等待外部材质插件加载完成后，执行 `/cc reload` 刷新图标缓存
3. 检查控制台是否有对应外部插件的加载报错

## 6. 不小心误清理了玩家的贵重物品如何恢复

CyuClear 内置批次持久化机制：
1. 管理员输入 `/cc runs` 查看最近清理的批次列表与时间
2. 点击对应批次或输入 `/cc run <批次ID> details` 查看该次清理的所有物品详情与坐标
3. 输入 `/cc recover <批次ID>`，该批次被清除的掉落物和实体将原样撤销回退到原地

## 7. Folia 服务端报调度负载警告

如果日志中提示 Folia 清理参数较激进，说明当前服务器的活跃区域任务数已达上限。可打开 `config.yml`，在 `performance` 下适当降低 `scan.max-chunks-per-tick`（如从 600 降为 300）与 `scan.max-millis-per-tick`（降为 10ms），即可使多区域调度更加平滑
