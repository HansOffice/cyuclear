CyuClear 使用文档

CyuClear 是一个轻量实体清理插件，支持周期清理掉落物与游荡实体、清理前倒计时提示、单区块硬限制、panic 紧急清理、实时实体拦截和虚空垃圾桶取回

可用来控制掉落物堆积、装饰实体滥用、抛射物刷屏和恶意刷实体，同时通过黑白名单保护贵重物品、命名实体、驯服宠物和指定世界

周期清理 虚空垃圾桶 单区块硬限制 模组实体识别

安装

把插件 jar 放入服务器 plugins 目录后重启服务器，首次启动会生成主配置、规则、存储、垃圾桶、音效、语言和 menu 菜单目录

选择文件

1.13 及以上的普通 Bukkit / Paper 服务端使用 cyuclear-paper-1.4.0.jar；Folia 服务端使用 cyuclear-folia-1.4.0.jar；1.8 到 1.12 的老版本服务端使用 cyuclear-legacy-1.4.0.jar

当前版本

当前文档对应 1.4.0，配置文件以默认生成内容为准

软依赖

支持 PlaceholderAPI、MythicMobs、CraftEngine、Cobblemon / Pixelmon，并可按 RoseStacker / WildStacker 的实际堆叠数量统计、清理和恢复物品

三个 jar 只需要放一个。低版本服务端请直接使用 Legacy 版，不要把多个版本同时放进 plugins 目录
Legacy 版的 ActionBar 提示会显示在聊天栏；BossBar 在 1.8 至 1.12 不可用。需要跨服同步时，Legacy 子服同样可以选择 Redis 或 MySQL，但所有子服必须使用同一个后端构建包

第一次上线

首次启动保持关闭

全新安装的 config.yml 默认使用 enabled: false，不会清理、拦截内容或参与跨服清理

调整清理范围

检查 rules.yml 的模块、名单、实体保护与区块上限，把服务器里的插件物品、动物、NPC 和功能实体纳入规则

检查并预演

使用 /cc check 检查目标，再用 /cc preview 查看整次清理预计影响，预演不会删除内容

开启总开关

确认配置完成后将 config.yml 的 enabled 改为 true，再执行 /cc reload

/cc reload 会应用总开关。改为 false 后重载，会停止自动清理、区块限制、紧急监控和跨服连接
升级已有配置时会保留原来的清理间隔、名单、阈值、保护规则、垃圾桶和连接配置；只有全新安装默认关闭总开关

规则文件导览

rules.yml 按服主实际调整顺序排列。先找到掉落物或实体，再依次查看基础设置、名单、保护和高级规则

板块配置路径主要内容
命名规则rules按优先级组合物品或实体条件
掉落物规则targets.items开关、名单模式、掉落保护时间、物品 ID、展示名和 Lore
实体规则targets.entities开关、名单模式、实体 ID、保护、名称和深度规则
特殊实体识别hooksMythicMobs、CraftEngine、Cobblemon 与 Pixelmon 的识别和保护
数量限制limits单区块软硬限制、实时出生拦截和全服紧急清理
默认配置保留字段说明和容易配错的写法。复杂组合示例集中在本文档，修改时不需要删掉注释

自动清理

config.yml 顶层的 enabled 是插件总开关；cleanup 控制周期清理间隔、倒计时提示点和提示输出方式

enabled: false

cleanup:
  interval-seconds: 600
  warning-times: [60, 30, 10, 3]
  warning-output:
    chat: true
    actionbar: false
    bossbar: false
配置 说明
enabled 插件总开关；全新安装默认关闭，修改后执行 /cc reload 生效
interval-seconds 自动清理循环间隔，单位秒
warning-times 清理前多少秒发送提示
warning-output.chat 是否在聊天栏广播倒计时
warning-output.actionbar 是否在提示点用 ActionBar 显示倒计时
warning-output.bossbar 是否在提示点用 BossBar 显示倒计时
清理速度由 performance 控制。Paper / Legacy 按时间预算让出主线程，Folia 按区域任务批次派发

性能策略

performance 控制清理器的处理速度和统计输出。Paper / Legacy 使用时间预算平滑扫描，Folia 使用区域任务批次派发，避免一次性把所有已加载区块塞进调度器

performance:
  profile: "快速"
  scan:
    max-chunks-per-tick: 240
    max-millis-per-tick: 7
  candidate-index:
    enabled: true
    full-scan-every-cycles: 6
  folia:
    max-active-region-tasks: 512
    dispatch-chunks-per-tick: 512
  stats:
    detail: true
    stage-timing: false
实服调参时先看 /cc status：档位、每 tick 区块与预算、候选索引待扫数量、上次清理耗时。卡顿时先把 profile 调到「均衡」或降低 max-chunks-per-tick。
candidate-index 定时清理优先处理近期出现实体的区块，并按轮次执行全量校准；手动与紧急清理始终全量扫描
配置 说明
profile 清理速度档位，支持 保守、均衡、快速、极限
scan.max-chunks-per-tick Paper / Legacy 每 tick 最多处理多少个区块
scan.max-millis-per-tick Paper / Legacy 每 tick 最多占用多少毫秒，到预算后让出
folia.max-active-region-tasks Folia 同时运行的区域清理任务数量
folia.dispatch-chunks-per-tick Folia 每 tick 最多派发多少个区块任务
stats.detail 清理完成后在控制台输出区块数、扫描实体数、实际处理耗时和最慢区块
stats.stage-timing 额外输出快照、过滤、移除、垃圾桶和审计耗时；平时保持关闭，排查性能时临时开启
玩家提示使用友好耗时，例如 低于 1 秒、1.2 秒、1 分 8 秒，避免直接显示一串毫秒。排查速度时看控制台性能统计：total 是分批跨区块处理的总时长，work 是实际执行清理逻辑的耗时，maxChunk 是最慢区块。Folia 服加载区块多时，total 高但 work 低是正常的限速保护

单区块数量限制分为软限制和硬限制。达到软限制后，只拦截按现有规则本来就会被清理的新对象；达到硬限制后停止继续堆积。安装 RoseStacker 或 WildStacker 时，统计、清理、垃圾桶恢复和审计会按实际堆叠数量处理

清理原因汇总

audit 会在清理结束后按实体类型和原因聚合输出，方便排查某次清理到底删了什么

audit:
  enabled: true
  max-lines: 30

掉落物规则

掉落物规则写在 rules.yml 的 targets.items。配置依次分为基础设置、掉落保护时间、物品 ID、展示名和 Lore；物品 ID 同时支持原版、ItemsAdder、CraftEngine 与 Oraxen

选择名单模式

黑名单

默认清理，keep-list 写不能清理的贵重物品

白名单

默认保留，clean-list 只写确定要清理的物品

并行名单

默认保留，清理名单写大范围，保留名单再写例外

示例：保护贵重掉落物

保持黑名单模式，把不能误清的物品写进保留名单

targets:
  items:
    mode: "黑名单"
    keep-list:
      match-mode: "精确"
      list:
        - "minecraft:diamond"
        - "minecraft:nether_star"
        - "minecraft:elytra"
        - "通配:minecraft:*_shulker_box"
        - "通配:minecraft:*_smithing_template"

示例：只清理圆石和腐肉

白名单模式默认保留其他掉落物，只有清理名单里的物品会被处理

targets:
  items:
    mode: "白名单"
    clean-list:
      match-mode: "精确"
      list:
        - "minecraft:cobblestone"
        - "minecraft:rotten_flesh"

示例：精确保留插件物品

安装对应插件后，CyuClear 会从掉落的 ItemStack 反查真实自定义 ID。把 ID 写进 keep-list，就能只保护指定的 IA、CraftEngine 或 Oraxen 物品，不必把共用同一种原版材质的其他物品一起保留

来源推荐写法兼容写法
ItemsAdderia:命名空间:物品itemsadder:命名空间:物品
CraftEnginece:命名空间:物品craftengine:命名空间:物品
Oraxenox:物品oraxen:物品
 
targets:
  items:
    mode: "黑名单"
    keep-list:
      match-mode: "精确"
      list:
        - "ia:iasurvival:ruby"
        - "ce:default:ancient_coin"
        - "ox:quest_key"

同样的写法也能用于 clean-list、grace.high-value-list 和 limits.chunk.items.specific。识别顺序是插件专属 ID、CustomModelData、原版材质，因此旧规则无需修改；看着掉落物执行 /cc check 可以直接查看插件识别出的推荐 ID

只有对应物品插件已安装并正常启用时，专属 ID 才能被识别。插件缺失或 API 不可用时会安全回退到 CustomModelData 与原版材质规则

示例：按 CustomModelData 区分物品

1.14 及以上可以使用 材质#CustomModelData。插件会先匹配具体编号，再回退到纯材质规则

targets:
  items:
    keep-list:
      list:
        - "minecraft:diamond_sword#1001"
        - "minecraft:paper#2005"
1.12 及以下没有 CustomModelData，带 # 的规则不会命中，低版本请填写纯材质 ID

示例：按展示名保留或清理

targets:
  items:
    name-rules:
      enabled: true
      color-mode: strip
      require-custom-name: true
      force-clean: false
      keep-list:
        match-mode: "精确"
        list:
          - "钻石斧"
          - "通配:*神器*"
      clean-list:
        match-mode: "精确"
        list:
          - "垃圾"
          - "通配:*测试*"

color-mode: strip 会先去掉颜色再匹配。开启 force-clean 后，展示名清理规则可以压过材质保留规则

示例：按 Lore 判断

targets:
  items:
    lore-rules:
      enabled: true
      color-mode: strip
      line-mode: any
      force-clean: false
      keep-list:
        list:
          - "灵魂绑定"
          - "通配:*不可交易*"
      clean-list:
        list:
          - "一次性"
          - "通配:*测试*"

line-mode: any 表示任意一行命中即可；改成 all 后，每条规则都要在某一行命中

掉落保护时间

普通掉落物和贵重物品可以分别设置最短存在时间，避免刚掉地就被周期清理带走

targets:
  items:
    grace:
      minimum-age-seconds: 10
      high-value-minimum-age-seconds: 60
      high-value-list:
        - "minecraft:diamond"
        - "minecraft:nether_star"
        - "minecraft:elytra"

实体名单

实体规则写在 rules.yml 的 targets.entities。先配置实体 ID 名单和安全保护，再按需要使用名称规则或深度规则

示例：保护常见生物和装饰实体

targets:
  entities:
    mode: "黑名单"
    protections:
      named: true
      tamed: true
      player-owned-pokemon: true
      persistent: false
      no-despawn: true
      events:
        raid: true
    keep-list:
      match-mode: "精确"
      list:
        - "minecraft:villager"
        - "minecraft:armor_stand"
        - "minecraft:item_frame"
        - "minecraft:painting"
        - "通配:minecraft:*boat"
        - "通配:minecraft:*minecart"

示例：只清理指定实体

白名单模式默认保留其他实体，适合只处理已经确认的对象

targets:
  entities:
    mode: "白名单"
    clean-list:
      match-mode: "精确"
      list:
        - "minecraft:arrow"
        - "minecraft:fireball"
        - "minecraft:shulker_bullet"

示例：指定实体不享受命名保护

有些装饰实体会被其他插件批量命名，可以让它们继续按照名单判断

targets:
  entities:
    protections:
      named: true
      named-bypass:
        entities:
          - "minecraft:armor_stand"
          - "minecraft:item_display"

示例：指定区域不使用命名保护

targets:
  entities:
    protections:
      named-bypass:
        regions:
          display-area:
            world: "world"
            min: { x: 0, y: -64, z: 0 }
            max: { x: 100, y: 320, z: 100 }
这里只跳过命名保护，实体仍会继续经过保留名单、清理名单和名单模式判断

实体名称

指令直接召唤并设置名称的实体同样拥有 Bukkit customName，不需要命名牌。名称规则支持精确、通配和正则，并可选择匹配前是否去除颜色

示例：保留商店与剧情实体

targets:
  entities:
    name-rules:
      enabled: true
      color-mode: "去除"
      require-custom-name: true
      keep-list:
        match-mode: "通配"
        list:
          - "*商店*"
          - "剧情 NPC -*"

示例：清理指定名称的召唤怪

targets:
  entities:
    name-rules:
      enabled: true
      color-mode: "去除"
      require-custom-name: true
      clean-list:
        match-mode: "正则"
        list:
          - "^测试怪物\\d+$"
      clean-bypasses:
        - "named"
clean-bypasses 很关键：默认的命名保护开启时，名称清理名单必须显式绕过 named 才能真正清理。它不会绕过玩家、NPC 或受保护的 CraftEngine 家具

实体深度规则

深度规则把多个维度组合成一个有名字、可检查的规则。match: all 要求所有已填写条件同时命中；match: any 只需任意条件命中

示例：只清理空载的临时展示实体

targets:
  entities:
    detail-rules:
      clean-temporary-display:
        action: "clean"
        match: "all"
        ids:
          match-mode: "精确"
          list:
            - "minecraft:armor_stand"
        names:
          color-mode: "去除"
          match-mode: "通配"
          list:
            - "临时展示-*"
        states:
          has-passengers: false
        bypass-protections:
          - "named"
          - "no-despawn"

示例：用计分板标签保护脚本实体

targets:
  entities:
    detail-rules:
      keep-scripted-wave:
        action: "keep"
        match: "any"
        scoreboard-tags:
          match-mode: "精确"
          list:
            - "cyuclear.keep"
            - "event_wave"

可组合的状态

状态字段含义
named / tamed是否命名、是否驯服
persistent / no-despawn持久标记、是否不会远离消失
in-raid是否正在参与袭击
player-owned-pokemon是否为玩家拥有的宝可梦
has-passengers / has-vehicle是否搭载乘客、是否正在乘坐其他实体
计分板标签匹配适用于 Paper 与 Folia。Legacy 1.8–1.12 不提供 Bukkit scoreboard tags API，因此该条件不会命中；名称、ID 和其他兼容状态仍可使用。深度规则只参与周期清理，不套用到实时出生拦截

命名规则

需要把多项条件写成一条明确规则时，使用 rules。规则按 priority 从大到小处理；同优先级按文件顺序。命中后默认结束，只有写入 stop-processing: false 时才继续检查下一条

示例：保护活动奖励

rules:
  protect-event-rewards:
    priority: 100
    target: "物品"
    action: "保留"
    conditions:
      match: "全部"
      ids:
        match-mode: "通配"
        list:
          - "ia:event:*"
      lore:
        color-mode: "去除"
        match-mode: "通配"
        list:
          - "*活动奖励*"

示例：清理临时展示实体

rules:
  clean-temporary-display:
    priority: 80
    target: "实体"
    action: "清理"
    conditions:
      ids:
        match-mode: "精确"
        list:
          - "minecraft:armor_stand"
      names:
        color-mode: "去除"
        match-mode: "通配"
        list:
          - "临时展示-*"
      states:
        has-passengers: false
    bypass-protections:
      - "named"
      - "no-despawn"
条件适用对象
ids、names、worlds、height、age物品、实体
lore物品
scoreboard-tags、states实体

age.minimum-seconds 和 age.maximum-seconds 按对象已存在的时间判断；height.min 与 height.max 按所在高度判断。物品 ID 可以直接写 minecraft:paper#2005，用于匹配 CustomModelData

targets.entities.detail-rules 会继续按原方式生效。需要让物品和实体使用同一套优先级时，再新增 rules 条目。命名规则也会参与已开启的实时出生拦截

实体保护与优先级

判定顺序为：不可绕过保护 → 命名规则 → 名称/深度保留 → 带显式绕过的名称/深度清理 → 普通保护 → 区域规则 → 基础实体名单 → 默认动作

保护能否被深度规则绕过
玩家、NPC、受保护的 CraftEngine 家具不能
命名、驯服、持久、不自然消失、袭击、玩家宝可梦仅 clean 规则显式写入 bypass-protections 时可以

可写的绕过名为 named、tamed、persistent、no-despawn、raid、player-owned-pokemon

管理员看着实体执行 /cc check，可以看到自定义名称、计分板标签、乘坐状态、命中的深度规则以及本次允许绕过的保护

特殊实体

MythicMobs、CraftEngine 和宝可梦实体可以直接写进实体保留名单或清理名单。先写实际目标，只有需要关闭识别或调整保护时再修改 hooks

MythicMobs 示例

使用 mythic:内部ID。下面的 Boss 会被保留，普通 MythicMobs 继续按照当前名单模式处理

targets:
  entities:
    keep-list:
      list:
        - "mythic:example_boss"
        - "mythic:dungeon_guardian"

如果需要关闭识别，设置 hooks.mythic-mobs.enabled: false

CraftEngine 家具示例

使用 ce:命名空间:家具ID。默认配置会保护全部 CraftEngine 家具部件

# 保留指定家具
targets:
  entities:
    keep-list:
      list:
        - "ce:server:wooden_chair"
        - "ce:server:display_table"

# 保留全部 CraftEngine 家具
        - "通配:ce:*"
若要让家具改由名单决定，先设置 hooks.craft-engine.protect-furniture: false。保持默认值时不必重复填写全部家具

宝可梦示例

Cobblemon 与 Pixelmon 都使用 pokemon: 规则。默认会保护玩家放出来的宝可梦

# 保留闪光、神兽和幻兽
targets:
  entities:
    keep-list:
      list:
        - "pokemon:shiny=true"
        - "pokemon:tag=legendary"
        - "pokemon:tag=mythical"
# 只清理指定宝可梦
targets:
  entities:
    mode: "白名单"
    clean-list:
      list:
        - "pokemon:species=magikarp"
        - "pokemon:species=zubat"
# 清理全部 Cobblemon 宝可梦
# 这也会包含闪光、神兽和幻兽
targets:
  entities:
    protections:
      player-owned-pokemon: false
    mode: "白名单"
    clean-list:
      list:
        - "pokemon:mod=cobblemon"
规则匹配内容
pokemon:shiny=true闪光宝可梦
pokemon:tag=legendary神兽标签
pokemon:tag=mythical幻兽标签
pokemon:tag=ultra_beast究极异兽标签
pokemon:generation=1指定世代
pokemon:species=articuno指定物种
pokemon:form=galarian地区形态或特殊形态
pokemon:palette=shinyPixelmon 配色
pokemon:owned=true玩家放出来的宝可梦
多条规则是任意一条命中即可，保留名单的优先级始终高于清理名单

匹配写法

掉落物和实体名单使用相同的精确、通配和正则写法

三种匹配方式

方式示例结果
精确minecraft:diamondID 完全一致才命中
通配minecraft:*_spawn_egg* 代表任意内容，? 代表一个字符
正则^minecraft:.*_boat$按正则表达式匹配
 
keep-list:
  match-mode: "精确"
  list:
    - "minecraft:diamond"
    - "通配:minecraft:*_shulker_box"
    - "正则:^minecraft:.*_boat$"

单条规则带前缀时使用自己的匹配方式，没有前缀的规则使用当前名单的 match-mode

判定顺序

顺序结果
硬保护玩家、NPC 和已开启的实体保护项直接保留
保留名单命中后保留，优先于清理名单

实时拦截

实时拦截会在实体出生或抛射物发射时直接取消事件，只应填写需要出生即阻止的对象

limits:
  realtime:
    enabled: true
    mode: "白名单"
    clean-list:
      match-mode: "精确"
      list:
        - "minecraft:shulker_bullet"
        - "minecraft:wither_skull"
        - "minecraft:fireball"
        - "minecraft:dragon_fireball"
普通周期清理请使用实体规则。实时拦截不会等待倒计时，也不会让实体先生成再清理

硬限制与紧急清理

数量限制写在 rules.yml 的 limits。这里依次包含单区块软硬限制、实时出生拦截和全服紧急清理

实体硬限制默认使用安全模式：实体生成事件里只记录短时间生成压力，不直接读取 chunk.entities。需要限制区块内当前实体总量时，把模式改为“严格”；严格模式只在实体出生和抛射物发射入口读取当前区块，并沿用短时计数缓存，不在默认安全模式增加扫描

limits:
  chunk:
    items:
      soft-threshold: 1000
      threshold: 1600
      specific:
        minecraft:stone: 80
        minecraft:cobblestone: 120
        minecraft:diamond: 10
    entities:
      mode: "安全"
      soft-threshold: 300
      threshold: 500
      spawn-window-millis: 1000
      specific:
        minecraft:armor_stand: 30
        minecraft:item_frame: 50
        mythic:example_mob: 10
    notice-target: "管理员"
    notice-cooldown-seconds: 60
    count-cache-millis: 250
    overload-cache-millis: 2000
配置 说明
limits.chunk.items.soft-threshold 默认 1000；达到后只拦截按掉落物规则本来就会被清理的新物品
limits.chunk.items.threshold 默认 1600；达到后拦截新掉落物生成，写 0 关闭总数量限制
limits.chunk.items.specific 为指定掉落物设置单独阈值，支持 minecraft:item、ia:、ce: 和 ox:，未配置的物品继续使用全局掉落物阈值
limits.chunk.entities.mode “安全”按短时间生成压力拦截；“严格”按区块当前实体总量拦截新的实体和抛射物；“关闭”不拦截实体
limits.chunk.entities.soft-threshold 默认 300；达到后只拦截按实体规则本来就会被清理的新实体
limits.chunk.entities.threshold 默认 500；安全模式按统计窗口内的新生成数量判断，严格模式按区块当前数量判断，写 0 关闭全局实体限制
limits.chunk.entities.spawn-window-millis 只影响安全模式的生成压力统计，默认 1000 毫秒；严格模式不按这个窗口计数
limits.chunk.entities.specific 为指定实体设置单独阈值，支持 minecraft:type、mythic:internalName 和 pokemon: 规则
limits.chunk.notice-target 区块保护提示发送给管理员、全服或不发送，默认只通知管理员
limits.chunk.notice-cooldown-seconds 同一区块同类提示冷却，避免高压点持续刷屏
limits.chunk.count-cache-millis 短时间计数缓存；严格模式用它保守估计刚放行的实体，减少高频生成时反复读取区块实体
limits.chunk.overload-cache-millis 区块过载后，在这段时间内直接拦截同类生成
升级插件不会覆盖已有服务器的自定义阈值。要限制区块当前实体总量，可把 mode 改为 严格；只想保留硬阈值时把 soft-threshold 写为 0

严格模式示例

limits:
  chunk:
    entities:
      mode: "严格"
      soft-threshold: 0
      threshold: 350
      spawn-window-millis: 1000
这个设置表示区块内实体数量达到 350 后，新的实体和抛射物不再进入；已经存在的超限实体不会被严格模式自动清掉，需使用周期清理或手动清理处理

熔断播报

messages.yml 里的 chunk-overload-warn 可以使用这些占位符：{world}、{chunk_x}、{chunk_z}、{x}、{y}、{z}、{type}、{id}、{count}、{threshold}、{duration}

chunk-overload-warn: "&#E74C3C[高压警报] &f{world} &7区块 &f{chunk_x},{chunk_z} &7坐标 &f{x} {y} {z} &7触发 &#E74C3C{type} &7熔断 &8({id} {count}/{threshold}，缓存 {duration}ms)"
overload-type-item: "掉落物"
overload-type-item-type: "指定掉落物"
overload-type-entity: "实体"
overload-type-entity-type: "指定实体"
overload-type-spawn-pressure: "生成压力"

Panic 模式

当全服实体总数突破极限值时，panic 模式会跳过倒计时，直接触发全服清理。清理动作不受提示接收范围影响

limits:
  panic:
    enabled: false
    notice-target: "管理员"
    max-global-entities: 5000
    check-interval-seconds: 15
配置说明
limits.panic.enabled是否在全服实体数量达到上限时跳过倒计时并立即清理，默认关闭
limits.panic.notice-target紧急提示和提示音发送给谁，可写“全服”“管理员”或“关闭”；缺少此项时保持全服提示
limits.panic.max-global-entities全服实体数量上限，达到后触发 panic 清理
limits.panic.check-interval-seconds每个世界的普查间隔，默认 15 秒
Panic 模式是保底保护，用于恶意刷实体或异常堆积阈值不要设置得太低，否则大型活动或刷怪塔高峰可能频繁触发

跨服同步

CyuClear 1.4.0 由每台总开关已启用的子服直接连接同一个跨服存储，连接信息填写在 storage.yml。可选择 Redis 或 MySQL；Redis 更适合高频状态同步，MySQL 需要 8.0 或更高版本。清理周期和共享垃圾桶始终由子服与这份存储决定

cluster:
  enabled: true
  id: "survival"
  # 每台子服必须唯一
  server-id: "survival-1"
  heartbeat-seconds: 1
  member-timeout-seconds: 20
  storage: "redis"
  redis:
    host: "127.0.0.1"
    port: 6379
    username: ""
    password: ""
    database: 0
    ssl: false
    connect-timeout-millis: 3000
    socket-timeout-millis: 3000

MySQL 示例

cluster:
  storage: "mysql"
  mysql:
    host: "127.0.0.1"
    port: 3306
    database: "minecraft"
    username: "cyuclear"
    password: "请使用强密码"
    ssl: false
    connect-timeout-millis: 3000
    socket-timeout-millis: 3000
    table-prefix: "cyuclear_"

允许互通的范围

  • 所有子服必须完全一致：CyuClear 版本、构建平台（Paper、Folia、Legacy）、Minecraft 版本、同步协议版本和物品序列化版本
  • Paper、Folia 与 Legacy 不允许混用。即使 Minecraft 版本相同，任一平台身份不一致也会拒绝加入集群
  • cluster.id 必须相同，server-id 必须在每台子服上唯一；重复 ID 会被拒绝
  • 所有子服必须指向同一份存储：Redis 的地址和数据库必须相同；MySQL 的地址、数据库和表前缀必须相同
  • 没有“强制兼容”开关。身份不匹配或存储断开时会停止同步定时清理并锁定共享垃圾桶，避免各服各自运行后产生错误状态

同步内容

集群只选出一个调度领导者生成清理周期和执行时间，各子服按同一个运行编号各执行一次本服扫描；领导者离线后由存活成员自动接管。垃圾桶物品按清理周期共享，写入批量合并。玩家取回时，物品会先在共享存储中预约给该玩家，成功交付后再完成预约；玩家离线或菜单失效时会释放预约，避免两台子服同时发放同一件物品

启用跨服同步后，只有同步定时清理会写入共享垃圾桶。手动、紧急和区块卸载清理仍会执行本服清理，但不会写入或重置共享物品；玩家也不能手动存入共享垃圾桶。这样不会让本地操作覆盖其他子服正在使用的恢复窗口

/cc cluster 会汇总最近一次同步清理的参与节点、物品数量、实体数量和最慢节点耗时，便于确认各子服是否在同一轮完成清理

如果服务器在“物品已经交给玩家、预约尚未来得及确认”的瞬间被强制终止，玩家下次进入时可能再次收到该预约中的物品。待交付预约独立保留 24 小时，不受垃圾桶窗口结束或下一轮清理影响；超过 24 小时的记录会在后续维护时移除。游戏背包与外部存储之间无法放进同一笔事务，本版本优先保留可恢复记录。短暂断线、玩家离线，以及仍连接同一份跨服存储时的 /cc reload 会继续处理已排队的完成或释放操作

Velocity / BungeeCord 代理端

跨服网络由每台子服直接连接 Redis 或 MySQL，代理端只负责在代理控制台查看这份状态。后端和代理端不需要互相发送插件消息，也不要把代理端当成清理执行节点

文件 放置位置 用途
cyuclear-paper-1.4.0.jar每个普通后端服的 pluginsPaper / Bukkit 后端清理本体
cyuclear-folia-1.4.0.jar每个 Folia 后端服的 pluginsFolia 后端清理本体
cyuclear-legacy-1.4.0.jar1.8 至 1.12 后端服的 pluginsLegacy 后端清理本体
cyuclear-velocity-1.0.jarVelocity 的 plugins代理端状态查看
cyuclear-bungee-1.0.jarBungeeCord 的 plugins代理端状态查看

代理端配置

代理端首次启动会在自己的插件数据目录生成 config.yml。把 cluster.id、storage、Redis 或 MySQL 连接信息、member-timeout-seconds 填成与子服 storage.yml 相同的值

cluster:
  id: "survival"
  storage: "redis"
  refresh-seconds: 10
  member-timeout-seconds: 20

Velocity 使用 cyuclear-velocity-1.0.jar，需要 Java 21；BungeeCord 使用 cyuclear-bungee-1.0.jar，需要 Java 17。代理端版本独立于后端版本；每个网络只放与当前代理软件对应的一个代理端 jar，不要把代理端 jar 放进任一子服，也不要把后端 jar 放进代理端

查看与重载

代理控制台或拥有 cyuclear.proxy.admin 的代理端管理员可使用 /ccproxy status 查看集群摘要，使用 /ccproxy reload 重载代理端配置和刷新间隔。代理端不参与领导者选举，不写入清理周期，也不写入共享垃圾桶物品

总开关关闭的子服不会连接共享存储，因此不会出现在代理端活跃成员中。将子服的 enabled 改为 true 并执行 /cc reload 后才会加入集群

请不要让多个服务器共用相同的 server-id，也不要混用构建平台或版本。可使用 /cc cluster 查看连接、身份、成员和领导者状态

虚空垃圾桶

清理掉落物时，插件可以把被清理的物品暂存到虚空垃圾桶。玩家在有效期内输入 /cc bin 可打开菜单取回误扫物品

void-bin:
  enabled: true
  always-open: false
  stacked-mode: false
  expire-seconds: 60
  warning-times: [30, 10, 3]
  warning-output:
    chat: false
    actionbar: true
    bossbar: false
  deposit-feedback:
    enabled: true
  deposit-buffer:
    enabled: true
  open-click:
    enabled: true
    command: "/cc bin"
  claim-cooldown:
    enabled: false
    seconds: 10
    bypass-permission: "cyuclear.admin"
配置 说明
enabled 是否启用虚空垃圾桶
always-open 是否允许玩家随时打开垃圾桶，关闭时只能在清理后的有效期内打开
stacked-mode 是否启用物品堆叠存放，按物品相似性累计数量并在菜单中拆成可拿取堆
expire-seconds 清理完成后垃圾桶开放多久
warning-times 垃圾桶关闭前的提示时间点
warning-output.chat 是否在聊天栏发送垃圾桶关闭倒计时
warning-output.actionbar 是否用 ActionBar 显示垃圾桶关闭倒计时
warning-output.bossbar 是否在提示点用 BossBar 显示垃圾桶剩余时间
deposit-feedback.enabled 本地模式下玩家手动存入物品时，是否发送成功提示；跨服同步时不允许手动存入
open-click.enabled 清理后是否把垃圾桶提示发送为可点击聊天文本
open-click.command 玩家点击聊天文本时执行的命令，默认 /cc bin
claim-cooldown.enabled 玩家成功取回一次物品后，是否需要等待冷却才能继续取回其他物品
claim-cooldown.seconds 取回冷却时间，单位秒，冷却只在成功拿走物品后开始
claim-cooldown.bypass-permission 拥有该权限的玩家不受取回冷却限制，默认是 cyuclear.admin

清理回收规则

这组规则只决定“被清理的掉落物是否进入垃圾桶”。命中禁止规则后，掉落物仍会按照 rules.yml 的结果正常清理，只是不提供取回

void-bin:
  entry-rules:
    cleanup-recovery:
      default: "允许"
      allow-list:
        match-mode: "精确"
        list:
          - "ia:server:quest_reward"
      deny-list:
        match-mode: "精确"
        list:
          - "minecraft:rotten_flesh"
          - "通配:ce:temporary:*"
      name-rules:
        enabled: true
        color-mode: strip
        allow-list:
          match-mode: "精确"
          list: ["活动纪念品"]
        deny-list:
          match-mode: "通配"
          list: ["临时物品*"]
      lore-rules:
        enabled: false
        color-mode: strip
        line-mode: any
        allow-list:
          match-mode: "精确"
          list: []
        deny-list:
          match-mode: "精确"
          list: []
allow-list 的优先级高于 deny-list。如果想只回收少数指定物品，把 default 改为 拒绝，再把允许回收的物品写入允许名单

玩家投放规则

这组规则用于玩家在垃圾桶菜单中点击背包物品。命中禁止规则、没有权限或达到种类上限时，原物会留在玩家背包，不会先移除再回退。启用个人投放缓冲区时，点击后会先进入玩家自己的待确认菜单，确认后才写入本地垃圾桶

void-bin:
  entry-rules:
    player-deposit:
      enabled: true
      permission: "cyuclear.bin.deposit"
      max-unique-items: 2048
      protect-cleanup-kept-items: true
      deny-non-empty-containers: true
      default: "允许"
      allow-list:
        match-mode: "精确"
        list: []
      deny-list:
        match-mode: "精确"
        list:
          - "minecraft:nether_star"
          - "通配:ia:quest:*"
      name-rules:
        enabled: false
        color-mode: strip
        allow-list:
          match-mode: "精确"
          list: []
        deny-list:
          match-mode: "精确"
          list: []
      lore-rules:
        enabled: true
        color-mode: strip
        line-mode: any
        allow-list:
          match-mode: "精确"
          list: []
        deny-list:
          match-mode: "通配"
          list: ["*不可丢弃*"]
配置说明
enabled是否允许玩家手动投放，不影响清理产生的回收物品
permission手动投放所需权限；留空则不额外检查投放权限，管理员始终可投放
max-unique-items玩家手动投放最多引入多少种不同物品，0 表示不限；不会限制清理回收
protect-cleanup-kept-items禁止投放 rules.yml 中明确命中物品 ID、展示名或 Lore 保留名单的物品
deny-non-empty-containers禁止投放装有内容的潜影盒和收纳袋；只检查玩家本次点击的容器，不递归扫描内部物品

个人投放缓冲区

void-bin.deposit-buffer.enabled 默认开启。玩家从背包点击物品后，插件先把这一笔投放写入玩家专属的缓冲文件，再从背包移出并打开独立的“投放缓冲区”菜单。只有点击“确认投放”后，物品才会一次性进入虚空垃圾桶。

void-bin:
  deposit-buffer:
    # true = 先进入个人缓冲区并确认；false = 点击后直接进入本地垃圾桶
    enabled: true
操作结果
确认投放再次检查权限、区域规则和种类上限，全部通过后批量写入本地虚空垃圾桶
点击物品图标左键取回 1 个，右键取回半组，Shift+左键取回 1 组，Shift+右键取回当前这类物品的全部数量
放回背包并关闭、直接关闭菜单尝试把待确认物品原样放回背包；空间不足的部分继续留在个人缓冲区
退出服务器、重载、垃圾桶到期或新一轮清理开始在线玩家优先回收至背包，离线玩家保留缓冲文件，下一次加入时继续恢复
个人缓冲区不参与跨服共享垃圾桶。跨服同步开启时仍禁止玩家手动投放；切换配置前已有的待确认物品会优先退回玩家背包，不会直接写入共享仓库
个人缓冲文件位于 plugins/cyuclear/deposit-buffer/<玩家 UUID>.yml，只由插件维护。不要手动改动其中的物品编码；如果读取失败，文件会保留并在控制台提示
两组入桶规则都支持原版物品、CustomModelData、ItemsAdder、CraftEngine 和 Oraxen ID，也支持精确、通配、正则、展示名和 Lore。直接沿用本文“匹配写法”中的格式
/cc check 看向掉落物时会分别显示清理结果、清理回收结果和玩家投放结果。玩家投放按玩家当前坐标判断，清理回收按掉落物所在坐标判断
缓冲区里的每个物品图标单独处理，不需要把其他待确认物品一起退回。背包空间不足时，未取回的数量继续留在缓冲区
潜影盒、各色收纳袋和带自定义数据的物品会作为完整物品保存。跨服模式会在清除潜影盒或收纳袋掉落物前校验回收快照；如果无法确认内容可以完整恢复，插件会保留原掉落物
垃圾桶菜单刷新会合并同一轮仓库变更，并先生成一次物品快照再分发给所有打开菜单的玩家。这样能保持多人看到的物品状态同步，也避免多人同时打开时重复构建物品页
若开启取回冷却，玩家每次成功取回后需要等待冷却结束才能继续拿下一件。点击打开垃圾桶的显示文本在 messages.yml 的 bin-open-click.text 和 bin-open-click.hover 中配置
always-open 只控制玩家能否随时打开当前垃圾桶，不会把垃圾桶变成永久仓库。下一轮清理开始或垃圾桶到期时，现有内容仍会按原逻辑清空
如果一次清理的处理过程出现异常，但其中一部分物品已成功保留，插件会照常开启这次垃圾桶有效期。即使 always-open 为 false，玩家也能在有效期内取回这些物品

清理批次与恢复

定时、手动和紧急清理结束后都会留下一个批次记录。记录会显示来源、时间、处理区块、清理数量和主要原因，可通过 /cc runs 或管理中心查看

个别区块处理失败时，批次会标记为「部分完成」，并保留最慢区块与首个异常，已经保存的恢复物品仍可领取，主动停止或重载中断的批次也是如此

恢复中心默认关闭。需要保留误清掉落物时，在 config.yml 的 recovery.enabled 改为 true，再按清理来源选择是否保存，已选来源的掉落物会进入恢复中心，不再写入虚空垃圾桶

recovery:
  enabled: true
  capture:
    scheduled: true
    manual: true
    panic: false
  max-entries-per-run: 256
  expire-hours: 72
  recent-limit: 50
配置说明
capture.scheduled保存定时清理的掉落物
capture.manual保存管理员手动清理的掉落物
capture.panic保存紧急清理的掉落物。紧急清理以减压为主，默认关闭
max-entries-per-run单个批次最多保存多少条物品。达到上限后清理继续进行，后续物品不会写入该批次
expire-hours恢复物品的领取时长，单位为小时
recent-limit管理中心和重启后保留的近期批次数量。早期批次文件不会被插件自动删除

领取恢复物品

找到批次

执行 /cc runs，或在 /cc menu 的管理中心进入「清理批次」

打开物品

选择需要检查的批次。已领取、已过期和无法读取的条目会保留原始状态，不会重复发放

确认领取

左键同一件物品两次后领取到管理员背包。背包空间不足时不会领取，也不会改变记录

恢复中心不会自动批量发放，也不会把物品丢回原坐标。每一条恢复物品都需要管理员单独确认

配置检查与快照

/cc doctor 会检查配置文件、版本、菜单布局和常见的名单写法；/cc snapshot 会保存当前配置。执行 /cc reload 前也会自动保存一份

快照保存在 plugins/cyuclear/backup/snapshots/，配置升级前会先备份旧文件

热点区块

当区块触发掉落物或实体限制时，CyuClear 会把它加入热点列表。执行 /cc hotspots，或在管理中心进入「热点区块」即可查看

limits:
  chunk:
    hotspot:
      enabled: true
      retention-seconds: 300
      max-records: 80
配置说明
enabled是否记录触发限制的区块
retention-seconds热点记录保留多久
max-records最多保留多少个热点区块

警告

区块达到软限制，但当前对象不在清理范围内

限流

区块达到软限制，开始拦截本来会被清理的新增对象

熔断

区块达到硬限制，按现有区块限制暂时拦截同类新增对象

恢复观察

熔断时间结束后暂时保留记录，方便确认问题是否反复出现

详情页会显示最近数量、近期触发、最近清理和处理耗时。「清理这个区块」只处理当前已加载区块；提前解除临时熔断时，左键「解除熔断」后再次确认

热点列表只记录触发过区块限制的区块，不会额外扫描全服已加载区块

世界与区域独立规则

areas.yml 可以让一张世界或两个角坐标之间使用独立规则。物品与实体分别支持继承、全部保留、全部清理、黑名单、白名单和并行名单；垃圾桶可独立覆盖清理回收与玩家投放。未命中区域时继续使用全局配置

areas:
  enabled: true
  rules:
    football-field:
      priority: 100
      worlds: ["world"]
      area:
        min: { x: -50, y: -64, z: -50 }
        max: { x: 50, y: 320, z: 50 }
      items:
        mode: "全部保留"
      entities:
        mode: "全部保留"
      void-bin:
        cleanup-recovery:
          default: "拒绝"
        player-deposit:
          default: "拒绝"
不写 area 时规则覆盖整张世界。重叠范围优先使用 priority 较大的规则；相同优先级按文件中的先后顺序判断。区域垃圾桶规则可使用 允许、拒绝、继承 及完整名单；全部清理 仍不会绕过玩家、NPC、命名、驯服和事件保护
模式 说明
blacklist 跳过列表里的世界，其他世界参与清理
whitelist 只清理列表里的世界
* / all 列表中可用来表示所有世界

常见问题

刚安装后为什么没有开始清理

全新安装的 1.4.0 默认使用 enabled: false。请按服务器实际情况调整配置，使用 /cc check 与 /cc preview 核对结果，再把总开关改为 true 并执行 /cc reload。升级已有数据目录时会迁移为已启用，严格实体总量模式需要在 rules.yml 中手动选择

代理端为什么看不到刚安装的子服

总开关关闭的后端不会连接代理端，也不会发送集群心跳。完成配置后把 enabled 改为 true 并执行 /cc reload 即可自动接入；随后可用 /cc cluster 查看连接状态

玩家输入 /cc bin 提示垃圾桶为空

如果 always-open 为 false，只有清理后且有效期内才能打开确认上次清理确实清到了掉落物

菜单里的 CraftEngine 图标显示为石头

确认菜单中的物品 ID 写成 ce:命名空间:物品ID，再执行 /cc reload。1.4.0 会在 CraftEngine 重载后重新读取菜单图标；仍显示石头时检查 ID 是否已在 CraftEngine 中注册，并查看服务器日志

潜影盒或收纳袋放进垃圾桶后会清空吗

1.4.0 会保留容器物品的完整数据，菜单展示信息也不会写回真实物品。跨服回收在删除原掉落物前还会验证容器快照；验证失败时，原掉落物会留在世界中，不会进入垃圾桶

钻石被清理了怎么办

默认配置里钻石写在 targets.items.keep-list.list，正常不会被清理；若仍被清理，检查是否仍为 minecraft:diamond，以及掉落物是否仍为黑名单模式

想只清理某些掉落物

把 targets.items.mode 改为 白名单，再把要清理的物品 ID 写入 targets.items.clean-list.list

已命名实体没有被清理

这是 targets.entities.protections.named: true 的保护行为。若只清理特定名称，请使用 targets.entities.name-rules.clean-list，并在 clean-bypasses 中写入 named；无需关闭所有命名实体保护。MythicMobs 也可通过 hooks.mythic-mobs.bypass-protection-flags 整体绕过普通保护

只让某些实体或建筑区域忽略命名保护

在 rules.yml 的 targets.entities.protections.named-bypass.entities 填实体 ID，或在 named-bypass.regions 填世界和两个角坐标。它只跳过命名保护，实体仍按保留名单、清理名单和其他保护判断

有人说实体命名后还是被清

先确认正在使用 1.4.0，再让管理员看着目标执行 /cc check。如果检查里显示“是否命名: 否”，说明那个名字不是 Bukkit 实体名，可能只是其他插件做的视觉显示

袭击事件里的怪被清理了怎么办

确认 targets.entities.protections.events.raid: true。CyuClear 会保护正在参与袭击的灾厄实体，但不会保护普通野外掠夺者。管理员可以用 /cc check 看目标是否显示“是否参与袭击: 是”

区块高压警报频繁出现

说明某个区块实体或掉落物生成太快先查看提示坐标，再处理源头机器、刷怪塔、结构生成或模组实体。默认提示只发给管理员；需要安静运行时把 limits.chunk.notice-target 改为“不发送”，不要为了隐藏问题而直接关闭实体保护

Mohist 混合端出现主线程卡在 RadarListener

1.4.0 的安全模式仍只记录短时间生成压力，不会在实体生成事件里读取 chunk.entities。如果要限制区块当前总量，请使用 cyuclear-folia-1.4.0.jar 并把 limits.chunk.entities.mode 改为“严格”；严格模式只在实体出生和抛射物发射入口读取当前区块

我把实体阈值设成 350，为什么箭矢还是能到几千

如果模式仍是“安全”，350 表示一个统计窗口内允许的新增实体压力，不是区块里同时存在的实体总数；箭矢分散在多个窗口生成时可以继续累积。把 mode 改为“严格”，并按需要把 soft-threshold 设为 0，再执行 /cc reload。严格模式只拦截之后的新实体和抛射物，已经堆在区块里的箭矢仍需周期清理或手动清理

清理提示太吵

可以关闭聊天提示，改用 ActionBar 或 BossBar；也可以在 sounds 里关闭对应音效

MythicMobs 怪物不按预期过滤

确认 MythicMobs 已安装，并检查 hooks.mythic-mobs.enabled如果希望只按 MythicMobs ID 判断，开启 hooks.mythic-mobs.id-only

需要查谁取走了虚空桶物品

开启 void-bin.claim-audit.enabled 后，成功发放的领取会写入插件数据目录 audit 下的按日账本。管理员使用 /cc history [玩家] [页码] 查看本服记录；条目会包含时间、玩家、所在节点、物品、数量和发放方式。

某个区块一加载就严重卡顿

如果区块能完成加载但实体活动会造成卡顿，可临时开启 emergency.chunk-load-sweep；卸载时清扫默认关闭，需要时再开 emergency.chunk-unload-sweep。若服务端在区块反序列化前已经崩溃，插件没有执行机会：先停服并备份世界文件，再使用离线区块工具处理实体数据，不要反复让玩家进入该区块。

配置建议

保守清理

掉落物可以保持黑名单模式，把钻石、下界之星、钥匙、礼包等高价值物品写入保留名单，再按服务器情况逐步补充规则

高压服务器

重点关注 limits.chunk.items.threshold、limits.chunk.items.specific、limits.chunk.entities.threshold、limits.chunk.entities.specific 和 limits.panic，这些阈值要按在线人数和刷怪塔规模调整

玩家活跃的生存服可以开启虚空垃圾桶，用来减少误扫后的争议。若服务器只清理明确无价值对象，也可以关闭垃圾桶，减少额外交互
CyuClear 配置有不确定的地方，先在测试服确认，再放到正式服
